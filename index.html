Introduction

What is Herz?

Herz (German for "heart") is the core infrastructure for Eaglercraft modding. It provides a build pipeline, a package format, a runtime loader, and a stable Java API — abstracting away the differences between Eaglercraft 1.8 and 1.12, and between JavaScript and WebAssembly compilation targets.

A Herz mod consists of:

  • A common Java module — your mod logic, written against the Herz API
  • Platform submodules — thin wrappers for desktop (LWJGL), TeaVM JS, and TeaVM WASM-GC
  • A manifest — herz-manifest.json describing the package for the runtime loader
📦

Package System

Mods are distributed as .hpckg archives — a ZIP containing compiled classes, resources, and a manifest. The runtime loads them at startup with no additional setup.

🔀

Bytecode Mixins

Hook into any Minecraft or Eaglercraft class via SpongePowered ASM. Declare targets in mixin-targets.json; Herz applies transforms before the class is first used.

⚡

Multi-Platform

One source, four outputs: common, desktop (LWJGL), teavm-js, teavm-wasm_gc. Build them all with a single Gradle task.

🌐

Registry API

Publish and resolve packages via a REST API — no local Herz installation needed. Curl your package into the registry; Herz pulls it at load time.

🛡️

EaglerStubs

Pre-generated stub JARs give you Eaglercraft's full API surface at compile time — without distributing the Eaglercraft source. Method bodies are stripped; only signatures remain.

🎛️

WebGUI

Overlay browser-rendered HTML on top of the game canvas. Build HUDs, menus, or settings screens in HTML/CSS — Herz bridges the JS ↔ Java boundary for you.

Supported versions: Eaglercraft 1.8.8 u53 (stable) and 1.12.2 u1 (new). Both versions share the same Herz API surface; version-specific behavior is isolated to the build configuration.
Getting Started

Quick Start

Requirements: JDK 17+, Git. Gradle is bundled via the wrapper — no global install needed.

  1. Clone the prototype

    Pick the folder matching your target Eaglercraft version.

    # Clone the prototype repo
git clone https://github.com/Admanatine/Herz-Prototype
cd Herz-Prototype

# For Eaglercraft 1.8.8 u53
cd 1.8

# For Eaglercraft 1.12.2 u1
cd 1.12

  2. Add stub JARs (or the Eaglercraft source)

    Herz builds against EaglerStubs — pre-compiled API surfaces that let you compile without the full Eaglercraft source tree. Download them from Herz-EaglerStubs and place them in your local Maven cache, or reference the paths directly in build.gradle.kts.

    # Stubs are in Herz-EaglerStubs, organized by version
git clone https://github.com/Admanatine/Herz-EaglerStubs
ls Herz-EaglerStubs/1.8/1_8_8_u53/
# base.jar  desktop.jar  javascript.jar  platform-api.jar  wasm_gc.jar
ls Herz-EaglerStubs/1.12/1_12_2_u1/
# base.jar  desktop.jar  javascript.jar  wasm_gc.jar

  3. Write your entrypoint

    Edit src/.../bootstrap/ClientInit.java. Herz calls ClientInit.init() after Minecraft finishes initializing.

    javapackage net.ada.bootstrap;
import net.ada.MyMod;

public class ClientInit {
    public static void init() {
        MyMod mod = new MyMod();
        mod.onLoad();
    }
}

  4. Build all platforms

    ./gradlew buildAllPlatforms

    This compiles the common module first, then delegates to teavm-js, teavm-wasm_gc, and desktop subprojects. Output lands in each subproject's build/ directory.

  5. Load your mod in Eaglercraft

    Copy the compiled output (or the assembled .hpckg from Herz-Compile) into Eaglercraft's mod directory. The Herz runtime loader picks it up automatically on next launch.

Build System

EaglerStubs

EaglerStubs are stub JARs generated from the Eaglercraft source tree using JarStubGenerator. Method bodies are stripped — only class signatures, field declarations, and method signatures remain. This lets you compile against Eaglercraft's API without distributing the source.

Available stubs

JARContents1.8.8 u531.12.2 u1
base.jar main + game + protocol-game sources ✓✓
desktop.jar base + lwjgl sources ✓✓
javascript.jar base + teavm-js platform ✓copy of base*
wasm_gc.jar base + wasm-gc-teavm platform ✓copy of base*
platform-api.jar 1.8-specific platform API ✓—

* 1.12.2 js/wasm_gc stubs are copies of base because the TeaVM eagler fork JARs (org.teavm.platform, org.teavm.interop) are not published to Maven Central — they're compiled from Eaglercraft source at build time.

Generating your own stubs

Use JarStubGenerator (in Herz-EaglerStubs/1.8/stubber/) to produce stubs from any JAR or source tree:

bash# Generate stubs from a compiled JAR
java -jar JarStubGenerator-1.1.0.jar \
  -f mylib.jar \
  -out ./stubs/

# The output JAR has identical class/method signatures,
# but all method bodies are replaced with throw stubs.

Using stubs in your build

kts// build.gradle.kts (common subproject)
dependencies {
    compileOnly(files("../../../stubs/1.12/1_12_2_u1/base.jar"))
    compileOnly(files("../../../stubs/1.12/1_12_2_u1/desktop.jar"))
}
Mod API

Mixins

Mixins are the primary way to hook into Minecraft and Eaglercraft internals. Herz uses SpongePowered ASM (via the classtransform library) to apply bytecode transforms before classes are first loaded by the JVM.

Declaring mixin targets

List your mixin classes in src/main/resources/mixin-targets.json:

json{
  "mixins": [
    "net.ada.mixins.GuiScreenMixin",
    "net.ada.mixins.MinecraftMixin"
  ]
}

Injecting into a method

@Inject runs your code at a specific point in a target method. HEAD runs before the first bytecode instruction; TAIL runs just before every return.

java@Mixin(Minecraft.class)
public class MinecraftMixin {

    // Runs after startGame() finishes — game is fully loaded
    @Inject(method = "startGame", at = @At("TAIL"))
    private void herz$onMinecraftInit(CallbackInfo ci) {
        Client.INSTANCE.getEventBus().fireEvent(
            MinecraftInitEvent.class,
            new MinecraftInitEvent()
        );
    }

    // Runs at the start of every game tick
    @Inject(method = "runTick", at = @At("HEAD"))
    private void herz$onTick(CallbackInfo ci) {
        Client.INSTANCE.getEventBus().fireEvent(
            TickEvent.class, new TickEvent()
        );
    }
}

Redirecting method calls

@Redirect replaces a specific method call inside a target method with your own implementation. Useful for intercepting input or rendering calls.

java@Mixin(GuiScreen.class)
public class GuiScreenMixin {

    // Intercept keyboard polling inside handleInput()
    @Redirect(
        method = "handleInput",
        at = @At(value = "INVOKE",
            target = "Lnet/lax1dude/eaglercraft/Keyboard;next()Z")
    )
    private boolean herz$onKeyboardNext() {
        boolean result = Keyboard.next();
        // your interception logic here
        return result;
    }
}

Mod API

Event Bus

Herz-Core ships a lightweight event bus. Mixins fire events; your mod code subscribes to them. No reflection at runtime — events are dispatched by direct method reference.

Built-in events

Event classFired whenMixin source
MinecraftInitEvent Minecraft.startGame() returns (TAIL) MinecraftMixin
TickEvent Start of each Minecraft.runTick() call MinecraftMixin

Subscribing to events

javaimport net.ada.api.eventbus.EventBus;
import net.ada.api.eventbus.events.impl.core.*;

public class MyMod {

    public void onLoad() {
        EventBus bus = Client.INSTANCE.getEventBus();

        bus.subscribe(MinecraftInitEvent.class, this::onInit);
        bus.subscribe(TickEvent.class,          this::onTick);
    }

    private void onInit(MinecraftInitEvent e) {
        // Game is fully loaded — safe to access Minecraft.getMinecraft()
    }

    private void onTick(TickEvent e) {
        // Runs every game tick (~20/sec)
    }
}

Firing custom events

java// Define your event
public class PlayerJumpEvent extends HerzEvent {
    public final double motionY;
    public PlayerJumpEvent(double motionY) {
        this.motionY = motionY;
    }
}

// Fire it from a mixin
Client.INSTANCE.getEventBus().fireEvent(
    PlayerJumpEvent.class,
    new PlayerJumpEvent(player.motionY)
);
Mod API

Package Format (.hpckg)

A Herz package is a ZIP archive with a .hpckg extension. It contains all compiled classes, resources, and a manifest. The runtime loader reads the manifest, applies mixins, and calls your entrypoint.

Archive layout

mymod-1.0.hpckg (ZIP) ├── herz-manifest.json # required: package metadata ├── mixin-targets.json # optional: mixin class list ├── classes/ # compiled .class files, preserving package structure │ └── net/ada/mymod/... └── resources/ # textures, lang files, sounds, etc. ├── assets/mymod/textures/ └── lang/

herz-manifest.json

json{
  "packageName":  "net.ada.mymod",
  "version":      "1.0.0",
  "authors":     ["yourname"],
  "platform":    "eagler/1_12_2",
  "permissions": [],
  "entrypoint":  "net.ada.mymod.bootstrap.ClientInit",
  "description": "My first Herz mod"
}

Manifest fields

FieldTypeRequiredDescription
packageNamestringyesReverse-domain package identifier. Must be unique in the registry.
versionstringyesSemver version string.
authorsstring[]yesList of author names.
platformstringyeseagler/1_8_8 or eagler/1_12_2
permissionsstring[]yesRuntime permissions requested. Currently unused; pass [].
entrypointstringyesFully qualified class name with a public static init() method.
descriptionstringnoShort description shown in the registry.

Assembling a package

Use Herz-Compile to assemble the .hpckg. It compiles all platform targets, packages classes + resources, and signs the archive:

./gradlew assembleHpckg

ls build/herz/
# mymod-1.0.hpckg
Build System

TeaVM Targets

Herz produces browser-runnable output via TeaVM — a Java-to-JavaScript and Java-to-WebAssembly compiler. The eagler fork of TeaVM includes custom runtime classes (org.teavm.platform, org.teavm.jso) that bridge to Eaglercraft's browser environment.

teavm-js

Compiles the entire Java codebase to a single classes.js file. The JS runtime is fastest to start and most compatible but produces larger files.

kts// teavm-js/build.gradle.kts (1.8.8 u53)
plugins {
    id("java")
    id("org.teavm") version "0.9.2"
}
dependencies {
    implementation(project(":common"))
    teavm("org.teavm:teavm-core:0.9.2")
    teavm("org.teavm:teavm-classlib:0.9.2")
    // Eagler stubs provide JSO bindings
    compileOnly(files("../../stubs/1.8/1_8_8_u53/javascript.jar"))
}

teavm-wasm_gc

Compiles to WebAssembly GC — a newer WASM feature that enables garbage-collected objects. Startup is slower than JS but runtime performance is significantly better. The eagler fork version differs between Eaglercraft versions:

Eaglercraft versionWASM-GC TeaVM forkGradle plugin ID
1.8.8 u530.12.1-EAGLER-R3org.teavm.wasm-gc
1.12.2 u10.11.0-EAGLER-R1org.teavm.wasm-gc
 
kts// teavm-wasm_gc/build.gradle.kts (1.12.2 u1)
plugins {
    id("java")
    id("org.teavm.wasm-gc") version "0.11.0-EAGLER-R1"
}
sourceSets {
    named("main") {
        java.srcDirs("src/wasm-gc-teavm/java")
    }
}
dependencies {
    implementation(project(":common"))
    compileOnly(files("../../stubs/1.12/1_12_2_u1/wasm_gc.jar"))
}
Source directories: The WASM-GC subproject has its own Java source directory (src/wasm-gc-teavm/java) for any WASM-specific glue code. Platform-agnostic logic lives in the common subproject.

desktop (LWJGL)

The desktop target compiles for the LWJGL-based Eaglercraft desktop client. It is not browser-deployable but is useful for development and testing without a browser.

kts// desktop/build.gradle.kts (1.12.2 u1)
application {
    mainClass.set("net.lax1dude.eaglercraft.internal.MainClass")
    // 1.8.8 uses: net.lax1dude.eaglercraft.lwjgl.MainClass
}
dependencies {
    implementation(project(":common"))
    compileOnly(files("../../stubs/1.12/1_12_2_u1/desktop.jar"))
    runtimeOnly(fileTree("desktopRuntime") { include("*.jar") })
}
Mod API

WebGUI

Herz-WebGUI lets you render browser-native HTML/CSS overlays on top of the game canvas. Useful for custom HUDs, mod settings screens, or any UI that's easier to build in HTML than in Minecraft's immediate-mode rendering.

How it works

  • The WebGUI module creates a transparent <div> overlay on top of the Eaglercraft canvas.
  • Your Java code calls WebGUI.show(String htmlContent) to inject HTML.
  • JavaScript events (button clicks, form inputs) are bridged back to Java via a message channel.
  • The overlay is hidden when the game is in a fullscreen 3D view and shown when a menu is open.

Basic usage

java// Show an HTML overlay
WebGUI.show("""
    <div id="mymod-hud">
        <span id="score">Score: 0</span>
    </div>
    """);

// Update a value without re-rendering the whole overlay
WebGUI.eval("document.getElementById('score').textContent = 'Score: " + score + "'");

// Hide the overlay
WebGUI.hide();
Security note: WebGUI overlays run in the same browser context as the game. Sanitize any player-supplied content before injecting it into HTML to avoid XSS.

Registry

Registry API

The Herz package registry is a REST API backed by Vercel serverless functions and Supabase Postgres. Use it to search for packages, resolve dependencies, and publish new releases — no local tooling required.

Base URL

https://herz-api.vercel.app/api

Endpoints

GET/packages
List or search packages.
namestring?Filter by package name (partial match)
platformstring?eagler/1_8_8 or eagler/1_12_2
authorstring?Filter by author name
limitnumber?Results per page (default 20, max 100)
pagenumber?Page number (1-indexed)
POST/packages
Publish a new package. Requires Authorization: Bearer <token>.
package_namestringReverse-domain package identifier
package_versionstringSemver version string
authorsstring[]List of author names
platformstringTarget platform ID
permissionsstring[]Requested permissions (pass [] for none)
manifestobject?Additional manifest fields (stored as JSONB)
GET/packages/:id
Fetch a package by UUID, internal numeric id, or name@version string.
DELETE/packages/:id
Delete a package. Requires Authorization: Bearer <token>. Same ID formats as GET.

Response format

{
  "packages": [{
    "id":              "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "package_name":   "net.ada.mymod",
    "package_version":"1.0.0",
    "authors":        ["yourname"],
    "platform":       "eagler/1_12_2",
    "permissions":    [],

curl examples

bash# List all 1.12 packages
curl "https://herz-api.vercel.app/api/packages?platform=eagler/1_12_2"

# Resolve a specific version
curl "https://herz-api.vercel.app/api/packages/net.ada.mymod@1.0.0"

# Resolve the latest version by name prefix
curl "https://herz-api.vercel.app/api/packages?name=net.ada.mymod&limit=1"

# Search by author
curl "https://herz-api.vercel.app/api/packages?author=yourname"

# Publish a package
curl -X POST \
  -H "Authorization: Bearer $HERZ_PUBLISH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"package_name":"net.ada.mymod","package_version":"1.0.0",
       "authors":["yourname"],"platform":"eagler/1_12_2",
       "permissions":[],"manifest":{"entrypoint":"net.ada.mymod.bootstrap.ClientInit"}}' \
  "https://herz-api.vercel.app/api/packages"

# Delete a package
curl -X DELETE \
  -H "Authorization: Bearer $HERZ_PUBLISH_TOKEN" \
  "https://herz-api.vercel.app/api/packages/net.ada.mymod@1.0.0"

Database schema

sqlCREATE TABLE packages (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    package_name    TEXT        NOT NULL,
    package_version TEXT        NOT NULL,
    authors         TEXT[]      NOT NULL DEFAULT '{}',
    permissions     TEXT[]      NOT NULL DEFAULT '{}',
    manifest        JSONB       NOT NULL DEFAULT '{}',

Registry

Publishing a Package

Publishing requires a HERZ_PUBLISH_TOKEN issued by an Admanatine admin. Contact the team on GitHub to request one.

  1. Build and assemble

    ./gradlew assembleHpckg
ls build/herz/
# net.ada.mymod-1.0.0.hpckg

  2. Set your token

    export HERZ_PUBLISH_TOKEN="your_token_here"

  3. Read the manifest

    cat build/herz/herz-manifest.json

  4. POST to the registry

    curl -X POST \
  -H "Authorization: Bearer $HERZ_PUBLISH_TOKEN" \
  -H "Content-Type: application/json" \
  -d @build/herz/herz-manifest.json \
  https://herz-api.vercel.app/api/packages

  5. Verify

    curl "https://herz-api.vercel.app/api/packages/net.ada.mymod@1.0.0"
Versioning: Package names and versions are immutable once published. To fix a bug, publish a new version (1.0.1). To yank a release, use the DELETE endpoint — but note that any Eaglercraft instances that cached the old manifest won't automatically update.

JarStubGenerator CLI

The stub generator is a standalone JAR — no Gradle integration needed:

bash# Generate stubs from a single JAR
java -jar JarStubGenerator-1.1.0.jar \
  -f input.jar \
  -out ./stubs/

# Generate stubs from multiple JARs (semicolon-separated)
java -jar JarStubGenerator-1.1.0.jar \
  -f "main.jar;game.jar;protocol.jar" \
  -out ./stubs/ \
  -outname combined-stubs

# Apply bytecode transforms (JarTransformer mode)
java -jar JarStubGenerator-1.1.0.jar \
  --transform \
  -f input.jar \
  -xform transforms.json \
  -out ./out/
