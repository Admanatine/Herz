Herz is a package and build system for Eaglercraft modding. Write once against a clean API, compile to JavaScript or WASM, ship as a self-contained .hpckg.

Getting Started

Quick Start

Clone the prototype for your target version and follow the steps below. Herz requires JDK 17+ and uses the Gradle wrapper — no global install needed.

  1. Clone the prototype

    Pick the folder matching your Eaglercraft version.

    # 1.8.8 u53
git clone https://github.com/Admanatine/Herz-Prototype
cd Herz-Prototype/1.8

# 1.12.2 u1
cd Herz-Prototype/1.12

  2. Add the Eaglercraft source

    Herz builds against stubs by default. To compile platform-specific targets, symlink or copy the Eaglercraft source tree into eagler-source/.

    # Or use pre-built stubs from Herz-EaglerStubs
ls 1.8/1_8_8_u53/    # base.jar  desktop.jar  javascript.jar  wasm_gc.jar
ls 1.12/1_12_2_u1/   # same set for 1.12.2 u1

  3. Build all platforms

    ./gradlew buildAllPlatforms

    This compiles the common module, then the teavm-js, teavm-wasm_gc, and desktop subprojects in order.

  4. Wire up your entrypoint

    Edit src/.../bootstrap/ClientInit.java to instantiate your client class. Herz calls ClientInit.init() after Minecraft finishes loading.

    public class ClientInit {
    public static void init() {
        Client client = new Client();
    }
}
Core Concepts

How Herz Works

Herz sits between your mod code and the Eaglercraft runtime. It handles compilation, bytecode transformation, and packaging so you write against a stable API regardless of which Eaglercraft version you target.

📦

Packages

Mods ship as .hpckg files — zip archives with a manifest, compiled classes, and resources. Herz-Compile assembles them; the runtime loads them at startup.

🔀

Mixins

Hook into Minecraft internals via SpongePowered ASM or classtransform. Declare targets in mixin-targets.json; Herz applies transforms at load time.

⚡

Multi-Platform

One source tree, four outputs: common (shared logic), desktop (LWJGL), teavm-js (JS), teavm-wasm_gc (WASM). Platform-specific code lives in dedicated subprojects.

🌐

TeaVM

Java→JS and Java→WASM-GC compilation via TeaVM. Herz configures the correct TeaVM version and eagler-fork dependencies per Eaglercraft version automatically.

🛡️

Stubs

Herz-EaglerStubs provides stub JARs (API surface only, no method bodies) so you can compile against Eaglercraft without distributing source. JarStubGenerator produces them from any source tree.

🎛️

Event Bus

Herz-Core ships a simple event bus. Mixins fire MinecraftInitEvent, TickEvent, and more. Subscribe with a plain method annotated @Subscribe.

Reference

Version Support

Herz targets two Eaglercraft versions. Build files and stubs are organized under 1.8/ and 1.12/ subfolders in each repo.

Property 1.8.8 u53 1.12.2 u1
platform ID eagler/1_8_8 eagler/1_12_2
TeaVM JS 0.9.2 0.9.2
TeaVM WASM-GC 0.12.1-EAGLER-R3 0.11.0-EAGLER-R1
Minecraft pkg net.minecraft.client.Minecraft (v1_8) net.minecraft.client.Minecraft
platform-api separate jar bundled in base
stubs repo 1.8/1_8_8_u53/ 1.12/1_12_2_u1/
desktop main ...lwjgl.MainClass ...internal.MainClass
Note: The 1.12.2 wasm_gc stubs use copies of base.jar because the TeaVM eagler fork JARs (org.teavm.platform, org.teavm.interop) are not available on Maven Central. They are pulled at build time from the Eaglercraft source tree.
Reference

Writing Mixins

Declare mixin classes in mixin-targets.json and annotate them with @Mixin. Herz uses SpongePowered ASM for both 1.8 and 1.12.

Declaring targets

json{
  "mixins": [
    "net.ada.mixins.GuiScreenMixin",
    "net.ada.mixins.MinecraftMixin"
  ]
}

Injecting into Minecraft

java@Mixin(Minecraft.class)
public class MinecraftMixin {

    @Inject(method = "startGame", at = @At("TAIL"))
    private void herz$onMinecraftInit(CallbackInfo ci) {
        Client.INSTANCE.getEventBus().fireEvent(
            MinecraftInitEvent.class, new MinecraftInitEvent()
        );
    }

    @Inject(method = "runTick", at = @At("HEAD"))
    private void herz$onTick(CallbackInfo ci) {
        Client.INSTANCE.getEventBus().fireEvent(
            TickEvent.class, new TickEvent()
        );
    }
}

Version differences

For 1.8.8, Eaglercraft classes live under the net.lax1dude.eaglercraft.v1_8 package. For 1.12.2, they're at net.lax1dude.eaglercraft (no version suffix). Use your build's common subproject for shared mixin logic and platform subprojects for platform-specific injections.

Class1.8.8 package1.12.2 package
Keyboard...v1_8.Keyboard...eaglercraft.Keyboard
Mouse...v1_8.Mouse...eaglercraft.Mouse
Minecraft...v1_8.client.Minecraft...client.Minecraft
GuiScreen...v1_8.client.gui.GuiScreen...client.gui.GuiScreen
Reference

Package Format

A Herz package is a .hpckg file — a ZIP with the following layout:

mymod-1.0.hpckg
├── herz-manifest.json   # package metadata
├── classes/             # compiled .class files
├── resources/           # assets (textures, lang, etc.)
└── mixin-targets.json   # optional, mixin class list

herz-manifest.json

json{
  "packageName": "net.ada.mymod",
  "version": "1.0.0",
  "authors": ["yourname"],
  "platform": "eagler/1_8_8",
  "permissions": [],
  "entrypoint": "net.ada.mymod.bootstrap.ClientInit"
}

herz-platform.json (build system)

Each version folder in Herz-1_8-Build carries a herz-platform.json that pins the Eaglercraft version and lists available subplatforms:

json{
  "platform": "eagler/1_12_2",
  "herzVersion": "0.0.0",
  "version": "u1",
  "author": "lax1dude",
  "subplatforms": {
    "desktop": "desktop",
    "common": "",
    "teavm-wasm_gc": "teavm-wasm_gc",
    "teavm-js": "teavm-js"
  }
}
Reference

TeaVM Targets

Herz produces browser-runnable output via TeaVM. Two targets are supported:

teavm-js

Compiles Java to JavaScript. The output is a single classes.js bundled with an HTML shell. Eaglercraft's custom JS APIs (org.teavm.jso.*) are provided by the eagler fork of TeaVM.

kts// teavm-js/build.gradle.kts (1.8)
dependencies {
    teavm("org.teavm:teavm-core:0.9.2")
    teavm("org.teavm:teavm-classlib:0.9.2")
}

// 1.12.2 uses the same teavm-js version

teavm-wasm_gc

Compiles Java to WebAssembly GC. Produces classes.wasm + a small JS bootstrap. The eagler fork version differs per Eaglercraft version:

VersionTeaVM WASM forkSource dir
1.8.8 u53 0.12.1-EAGLER-R3 src/wasm-gc-teavm/java
1.12.2 u1 0.11.0-EAGLER-R1 src/wasm-gc-teavm/java
Tip: The wasm-gc and teavm-js subprojects each have their own build.gradle.kts. They inherit the common compiled output via includeBuild() in settings.gradle.kts.
Registry

Registry API

The Herz package registry is a REST API hosted on Vercel + Supabase. Use it to search for and resolve packages without installing anything locally.

Base URL

https://herz-api.vercel.app/api

Endpoints

GET/packages
List or search packages. Query params: name, platform, author, limit, page
POST/packages
Publish a new package. Requires Authorization: Bearer <HERZ_PUBLISH_TOKEN>
GET/packages/:id
Fetch a package by UUID, internal id, or name@version
DELETE/packages/:id
Delete a package. Requires Bearer token.

Examples

bash# Search packages by platform
curl "https://herz-api.vercel.app/api/packages?platform=eagler/1_12_2"

# Fetch a specific package
curl "https://herz-api.vercel.app/api/packages/net.ada.mymod@1.0.0"

# Publish a package
curl -X POST \
  -H "Authorization: Bearer $HERZ_PUBLISH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"package_name":"net.ada.mymod","package_version":"1.0.0",
       "authors":["you"],"platform":"eagler/1_12_2","permissions":[]}' \
  "https://herz-api.vercel.app/api/packages"

# Delete a package
curl -X DELETE \
  -H "Authorization: Bearer $HERZ_PUBLISH_TOKEN" \
  "https://herz-api.vercel.app/api/packages/net.ada.mymod@1.0.0"
Registry

Publishing a Package

Publishing requires a token issued by an Admanatine administrator. Set it as the HERZ_PUBLISH_TOKEN environment variable, or pass it directly.

  1. Build your package

    ./gradlew buildAllPlatforms
ls build/herz/        # mymod-1.0.hpckg

  2. Upload the manifest

    POST the package metadata. Attach the .hpckg URL or bytes in the manifest field.

    curl -X POST \
  -H "Authorization: Bearer $HERZ_PUBLISH_TOKEN" \
  -H "Content-Type: application/json" \
  -d @build/herz/mymod-1.0-manifest.json \
  https://herz-api.vercel.app/api/packages

  3. Verify

    curl https://herz-api.vercel.app/api/packages/net.ada.mymod@1.0.0
